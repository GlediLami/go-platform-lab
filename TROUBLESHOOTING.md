# Troubleshooting: common errors in this lab

**Symptom, why, fix.** Most of these you'll also meet at work.

---

## Compile errors

**`declared and not used: x`** / **`"fmt" imported and not used`**
Go refuses unused variables and imports. Use them, delete them, or assign to `_` while experimenting. VS Code removes unused imports on save.

**`cannot use x (variable of type int) as int32 value`**
Go never converts numbers implicitly. Convert: `int32(x)`. Kubernetes uses `int32` for replicas.

**`cannot use &corev1.Pod{} (value of type *Pod) as client.Object`**
Usually a missing `&`: client methods take pointers (`c.Get(ctx, key, &pod)` or `pod := &corev1.Pod{}`).

**`missing method DeepCopyObject`**
A type stored in a scheme must implement `runtime.Object`. See `pkg/apis/lab/v1alpha1/zz_deepcopy.go` (generated by `controller-gen` in real projects).

## Test failures

**`no kind is registered for the type v1alpha1.Cluster in scheme ...`**
The client's scheme doesn't know the type. Use `fake.NewClientBuilder().WithScheme(labscheme.Scheme)` (or `ctrl.Options{Scheme: labscheme.Scheme}` for the manager).

**Status changes don't stick (status stays empty)**
You used `c.Update`. With a status subresource, `Update` ignores `.status`. Use `c.Status().Update(ctx, obj)`. The fake client only behaves like this when built with `.WithStatusSubresource(&v1alpha1.Cluster{})`, which the tests do.

**`Operation cannot be fulfilled on clusters ...: the object has been modified; please apply your changes to the latest version`**
A conflict: your object's `resourceVersion` is old because someone else wrote in between (another controller, a user). Return the error: controller-runtime retries with the fresh object. Patches (`client.MergeFrom`) conflict less than updates.

**`spec.selector: Invalid value: ... field is immutable`** (exercise 10 on a real cluster)
You changed the Deployment selector after creation. Set it only when `deployment.Spec.Selector == nil`.

**`WARNING: DATA RACE`** (exercise 05)
Two goroutines touched the same map/variable without a lock. The report shows both stack traces. Add a `sync.Mutex` around the shared write.

**Test hangs**
A goroutine waits on a channel nobody writes to, or `wg.Wait()` but some goroutine never called `wg.Done()`. Use `defer wg.Done()` as the first line in the goroutine. `go test -timeout 30s` makes hangs fail fast and prints all goroutine stacks.

**Ginkgo: `Ran 0 of 0 Specs`**
The `Describe` is in a file whose package doesn't match, or there's no `suite_test.go` with `RunSpecs`. Both files must be in the same package.

**Forgot to remove `FIt` / `FDescribe`**
Focused specs make Ginkgo skip everything else and fail the suite with "focused specs". Remove the `F`.

## Exercise 12 / envtest / kind

**`KUBEBUILDER_ASSETS is not set` (test skipped)**
Run through make: `make test EX=12`. It installs `setup-envtest` and points the test at the downloaded `kube-apiserver` and `etcd`.

**`unable to start control plane itself: failed to start the controlplane`**
Usually a leftover process or a blocked port. Rerun; check `ps aux | grep -E "etcd|kube-apiserver"` for leftovers from a killed run.

**`no matches for kind "Cluster" in version "lab.gardener.cloud/v1alpha1"`** (kind)
The CRD isn't installed in that cluster: `kubectl apply -f config/crd/`. Check `kubectl config current-context` is `kind-lab`.

**`go run ./exercises/12-manager/cmd` talks to the wrong cluster**
The manager uses your current kubeconfig context (`ctrl.GetConfigOrDie()`). Check with `kubectl config current-context`. Don't point it at the Gardener `gardener-local` cluster.

**Deployment isn't deleted after the Cluster is deleted (envtest only)**
Expected: envtest has no kube-controller-manager, so no garbage collector. On kind it is deleted.

**Pods stay `Pending` on kind**
Nothing to do with your code: check `kubectl describe pod`. The pause image must be pullable (a corporate web filter can block it).
